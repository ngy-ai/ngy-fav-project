## 手工添加一个仓库之后，自动把它选中

弘道：「手工添加一个仓库后，要选中这个仓库。」

**改动**（4 个文件）：

- `repos/add_repo_dialog.rs`：`open` / `submit` 多一个 `on_added: Fn(&str, &mut Window, &mut App)`
  回调，在 `AddOutcome::Added` 那一支里带上 id 调一次。沿用 `bulk_category_dialog::on_saved`
  那套（对话框不该认识列表）；多一个 `&mut Window` 是因为要调 `set_selected_index`。
- `repos/repos_view.rs`：新增 `select_added(&mut self, id, window, cx)` 与

- `repos/list_delegate.rs`：新增 `position_of(id) -> Option<usize>` + 一条测试。
- README：新增一段「手工添加一个仓库之后，它会被自动选中」；测试数 255。

**select_added 的顺序**（这几步的先后不能换）：

1. `self.selected = Some(id)` —— 详情面板立刻看它，不用等观察者那一轮。
2. `delegate.request_page(0)` —— 新加的仓库 `discovered_at` 就是现在，
   列表按 `discovered_at DESC, full_name ASC` 排，**它一定在第一页**。
3. `sync_page(cx)` —— 把第一页取回来。
4. `position_of(id)` → `set_selected_index(IndexPath::new(row))` + `scroll_to_selected_item`
   —— **行号是对着当前这一页解释的**，页还没换就选第 0 行，选中是别人。

**口径 / why**：

- **不碰筛选条件**。用户可能正看着某个分类，把他设的条件悄悄清掉，比「详情里是它、
  列表里没高亮」更让人意外。条件真把它挡住时（新加进来的既没分类也没标签），
  选中照样落到它身上（详情面板显示它），只是没有一行可高亮。
- 选中状态只有 delegate 一份（视图观察它、镜像给详情面板），所以落选中走
  `ListState::set_selected_index` 而不是自己改 `self.selected` 了事——前者顺带
  把列表内部的游标也指对，`scroll_to_selected_item` 才有得可滚。
- `scroll_to_selected_item` 是组件库里 **public** 的那个（`_set_selected_index` 会连带
  滚动，但它是 `pub(crate)`）；列表可能停在下面别处，选中了却看不见等于没选中。

**踩到的两处**：

- 我第一版 `list.update(cx, |state, _window, cx| ..)` 想在图里拿窗口，编译不过：
