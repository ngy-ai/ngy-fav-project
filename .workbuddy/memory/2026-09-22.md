# 2026-09-22

## 词表排序改成拖拽（分类页 / 标签页）

弘道的原话：「分类的排序，能做成拖动的吗？一个一个向上移，使用太麻烦了。」
上移/下移按钮**先留着**（做前后一格的精调），拖拽是主路径。

- `src/db/taxonomy.rs`：新增 `place_category` / `place_tag`，一步落到目标的前/后（`placed` 负责
  摘出来再插进去），**只在同级**——同父不同 → 返回 `false` 且一条都不改；顺手抽出 `category_parent`
  （两层 `Option`：外层说有没有这个 id，内层说是不是顶层），`reorder_category` 改成复用。
- `src/library.rs`：`CategoryRow` 加 `parent: Option<String>`（从树的 `parent_id` 取，不是切 path）；
  `place_name(kind, name, target, before)`；`MoveName` 加 `NotSibling`。
- `src/taxonomy/taxonomy_view.rs`：整行挂 `.on_drag` / `.on_drag_move` / `.on_drop`，载荷
  `DraggingName { name, level }`（`level` 是父路径，顶层空串）；落点线用**绝对定位**——进布局
  会让行高变化，鼠标一下就到行外，落点来回翻、线跟着闪。拖拽结束的残留落点在 `Render` 里
  用 `cx.has_active_drag()` 兜底清掉（松手的地方不一定有回调可挂）。
- **踩到的坑**：`on_drag_move` 的事件是发给**每个**元素的，不是只发给鼠标下面那一个。第一版没算
  `event.bounds.contains(&event.event.position)`，结果全表同级的行轮流设落点、最后看渲染顺序，
  表现是「拖了没反应」（测试第一次就栽在这）。另外每个行收到事件时不能无脑设 `None` 撤落点，
  否则会把真正落在的那一行刚设好的覆盖掉——`set_drop_hint(mine, hint, cx)` 只在落点还留在自己
  这儿时才撤。
- **`push_notification` 在没有 `Root` 的窗口里直接 panic**（`root.rs:163`：
  「BUG: window first layer should be a gpui_component::Root」）。跨层拒绝因此改成**静默** +
  页头说明（「只能和同级的换，要挪上级用改名改路径」），不再弹通知——不然那条跨层测试
  每次都炸。
- 验证：`cargo test` **213 passed / 0 failed / 2 ignored**（206 → 213：db 3 条、library 2 条、
  视图 2 条），`cargo clippy --all-targets` 无警告。拖拽那条是真拖：`window.drag` 走原生指针派发，
  「学习」拖到「工具」上半 → 插到前面，下半 → 后面；落点接不接另有一条纯函数测试。
