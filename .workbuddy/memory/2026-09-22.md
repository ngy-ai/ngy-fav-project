## 词表排序改成拖拽（分类页 / 标签页）

弘道的原话：「分类的排序，能做成拖动的吗？一个一个向上移，使用太麻烦了。」
上移/下移按钮**先留着**（做前后一格的精调），拖拽是主路径。

- `src/db/taxonomy.rs`：新增 `place_category` / `place_tag`，一步落到目标的前/后（`placed` 负责
  摘出来再插进去），**只在同级**——同父不同 → 返回 `false` 且一条都不改；顺手抽出 `category_parent`
  （两层 `Option`：外层说有没有这个 id，内层说是不是顶层），`reorder_category` 改成复用。
- `src/library.rs`：`CategoryRow` 加 `parent: Option<String>`（从树的 `parent_id` 取，不是切 path）；
  `place_name(kind, name, target, before)`；`MoveName` 加 `NotSibling`。
- `src/taxonomy/taxonomy_view.rs`：整行挂 `.on_drag` / `.on_drag_move` / `.on_drop`，载荷
  `DraggingName { name, level }`（`level` 是父路径，顶层空串）；落点线用**绝对定位**——进布局
  会让行高变化，鼠标一下就到行外，落点来回翻、线跟着闪。拖拽结束的残留落点在 `Render` 里
  用 `cx.has_active_drag()` 兜底清掉（松手的地方不一定有回调可挂）。
- **踩到的坑**：`on_drag_move` 的事件是发给**每个**元素的，不是只发给鼠标下面那一个。第一版没算
  `event.bounds.contains(&event.event.position)`，结果全表同级的行轮流设落点、最后看渲染顺序，
  表现是「拖了没反应」（测试第一次就栽在这）。另外每个行收到事件时不能无脑设 `None` 撤落点，
  否则会把真正落在的那一行刚设好的覆盖掉——`set_drop_hint(mine, hint, cx)` 只在落点还留在自己
  这儿时才撤。
- **`push_notification` 在没有 `Root` 的窗口里直接 panic**（`root.rs:163`：
  「BUG: window first layer should be a gpui_component::Root」）。跨层拒绝因此改成**静默** +
  页头说明（「只能和同级的换，要挪上级用改名改路径」），不再弹通知——不然那条跨层测试
  每次都炸。
- 验证：`cargo test` **213 passed / 0 failed / 2 ignored**（206 → 213：db 3 条、library 2 条、
  视图 2 条），`cargo clippy --all-targets` 无警告。拖拽那条是真拖：`window.drag` 走原生指针派发，
  「学习」拖到「工具」上半 → 插到前面，下半 → 后面；落点接不接另有一条纯函数测试。

已提交：`10a7a10`（10 个文件，+699 / −21）。未推送。

## 仓库列表加勾选框 + 全选 + 批量改分类

弘道的原话：「添加批量修改分类功能，仓库列表中每一项添加选择框，支持全选（筛选后台的结果）」。
括号里那个「后台」按「筛选**后**的结果」理解：全选要覆盖**筛出来的整批**（跨页），不是当前页。

- `src/db/repos.rs`：`set_category_bulk(conn, ids, Option<i64>)`（一条
  `UPDATE ... WHERE id IN (...)`，**空 ids 必须在拼 SQL 前返回 0**——sqlite 的 `IN ()` 是语法
  错误不是「不匹配」）与 `ids_matching(conn, spec)`（`SELECT r.id`，**刻意不带 LIMIT/OFFSET**）。
- `src/library.rs`：`repo_ids_matching(&RepoQuery)`、`set_repos_category(&ids, Option<&str>)
  -> Option<usize>`（`Db::transaction` 里整批写；返回**真被改到的条数**，内存镜像一趟
  `HashSet` 过滤改完）。`repo_ids_matching` 是唯一一条「整批 id」查询，顺带被
  `RepoQuery::page_size` 无用而用 `build_spec` 复用条件。
- `src/taxonomy/picker.rs`：`NONE_KEY` 与 `category_choice_rows()` 从 `taxonomy_dialog` 提到
  公共层（两个对话框都要那条「不分类」，key 只有一种写法）。
- `src/repos/list_delegate.rs`：`checked: BTreeSet<RepoId>` + `matching: Vec<RepoId>`；
  `SelectAll { None, Partial, All }`（`select_all_state`）；`toggle_select_all` 摘的是**匹配的
  那些**而不是整个勾选集合；行里加 `Checkbox`。
- `src/repos/repos_view.rs`：`render_batch_bar`（三态方框用
  `SquareCheck`/`SquareMinus`/`Square` 图标摆，组件库 `Checkbox` 只有两态）+
  `toggle_select_all` / `clear_checked` / `open_bulk_category`；`sync_page` 里多查一次整批 id，
  并把已删仓库从勾选里摘掉。
- `src/repos/bulk_category_dialog.rs`（新）：整批改分类，只动分类不动标签；`open` 收一个
  `on_saved: Fn(&mut App) + Clone + 'static`，保存成功后由列表把勾选清掉。
- **踩到的坑**：`Checkbox` 嵌在可点击的列表行里，点它**会**连带动到行的 `on_click`（详情面板
  跟着跳）。组件库 `Checkbox` 自己调的 `window.prevent_default()` 挡不住——它只管键盘激活的
  默认行为，鼠标点击的 listener 照走。解法是在勾选框外面那层挂
  `.on_mouse_up(MouseButton::Left, cx.listener(|_,_,_,cx| cx.stop_propagation()))`：
  MouseUp 冒泡时内层先跑，掐断之后外层行的 click 不会合成。`on_mouse_up` **要一个
  `MouseButton` 参数**（`on_click` 不用），这是编译报错才发现的。测试
  `the_checkbox_checks_without_stealing_the_row_click` 钉住了它。
- 验证：`cargo test` **229 passed / 0 failed / 2 ignored**（213 → 229：db 3、library 3、
  delegate 5、picker 1、批量对话框 3、视图 1），`cargo clippy --all-targets` 无警告。
  两条自测写错的地方已改：`ids_matching` 的期望顺序（同为发现时间时按 `full_name ASC`，
  不是「新的在前」）、`category_choice_rows` 的期望元组（key 是路径，不是叶子名）。

已提交：`f3834c9`（11 个文件，+1458 / −68）。未推送。

## 三栏的宽度可以拖

弘道的原话：「分的三栏要能调整各自的宽度」——侧栏 / 仓库列表 / 详情。

- `src/app.rs`：侧栏 ↔ 内容走 `h_resizable("app-shell")`；侧栏那一栏加 `sidebar_width: f32`
  （展开时该多宽）与 `dropped_column_width: Rc<Cell<f32>>`（分栏在鼠标松开时把宽度写进来）。
- `src/repos/repos_view.rs`：列表 ↔ 详情走 `h_resizable("repos-split")`，列表栏 240~560。
- 两边都在面板里包了一层挂 `test_support()` 的 div（`app-sidebar-column` / `repo-list-column`），
  因为是**量元素 bounds**才能证明「宽度真落到了布局上」，而组件本身挂不上观测点。
- **踩到的坑（三个，都写进技能了）**：
  1. 组件库的拖动把手在分割线左边 4px 里（`.absolute().left(-4).w(1px).px(4)`）——写了个
     探针测试逐个偏移量试出来的；无头窗口里 `window.drag(from=(w-2, y), to=...)` 命中。
  2. `resize_panel` 按**上一次绘制**记下的 `size_range` 夹宽度。收起侧栏时 `resize_panel(0, 48)`
     被展开时的 168 下限夹回 168；改走 `reset_panel` 再设宽度，又被 `0..0`（`ResizablePanelState`
     的 Default 是派生的，`Range::default()` 就是 `0..0`，不是组件里那个 `PANEL_MIN_SIZE..MAX`）
     夹成 0。最终：展开时的下限故意放到 48，收起直接设宽度；展开只 `reset_panel`，宽度交给
     渲染时的 `.size()`。
  3. `state.sizes()` 会过期（`reset_panel` 后停在旧值），第一版测试量它，量出来的数与布局
     不一致。改成量元素 bounds。
- 另外一个副作用：`Sidebar` 的宽度改写成 `w_full()`。写像素值会启用组件自带的宽度过渡动画，
  拖动时那动画（200ms）追不上光标；`w_full()` 正好让它不启用。代价是收起/展开不再有滑动过渡。
- 侧栏拖到 168 以下 = 松手自动收起（跟顶栏按钮一个效果），展开回到拖动记下的宽度——
  那个数只由**真实拖动**更新（`on_resize`，鼠标松开时）。
- 验证：`cargo test` **231 passed / 0 failed / 2 ignored**（229 → 231：视图 1、外壳 1），
  `cargo clippy --all-targets` 无警告。
